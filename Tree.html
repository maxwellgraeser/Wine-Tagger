🍷 Wine Warehouse DDD — Architecture Tree

A domain-driven data pipeline that turns raw Lightspeed exports into AI-enriched wine metadata for re-upload. Each domain is self-contained; data flows strictly downstream via file contracts (CSV → SQLite → XLSX).

Active focus: the fermentation/ domain, which drives a local LLM through a self-built MCP wine library to tag wines.

3 · library_mcp — The MCP Wine Library FastMCP · stdio · baked SQLite

A self-built MCP server is the project's signature design choice: instead of a post-hoc normalization pass, the model calls tools during inference. submit_tags is the contract — the model cannot ship a row the server hasn't canonicalized.

Validates & returns {ok, normalized} or {ok:false, issues, hints}. Issue codes: placeholder_grapes, no_grapes, non_canonical_grape, region_country_mismatch, country_in_region_slot, is_blend_mismatch.
library.db · baked SQLite, shipped in repo
Schema (schema.sql): keyed on Wikidata QIDs for dedup.
  • countries (id, name, iso_code, qid, is_canonical) + country_synonyms (USA → United States)
  • regions (self-ref parent_region_id → authored hierarchy, is_canonical) + region_synonyms (Piemonte → Piedmont)
  • grapes (canonical_name, color, origin, qid, is_canonical) + grape_synonyms (Garnacha → Grenache)
  • region_grapes (m:n grown-in, from the Italian Wikipedia list)
✓ Reseeded 2026-09-15 (two tiers): 46 countries · 675 canonical + 275 placeholder regions · 335 canonical + 375 placeholder grapes, every canonical grape coloured. Canonical = allowlist; placeholder = Wikidata long tail with an enwiki article, resolvable but rejected by submit_tags.
seed/ — one-shot offline build pipeline
build_db.py · ~500
Allowlist-driven: countries by ISO (P297), grapes by locked QID (VALUES SPARQL), regions straight from YAML; then the filtered placeholder pass, then Wikipedia enrichment (no minting). Rebuilds atomically — no migrations. --offline · --no-placeholders.
allowlist/ + resolve_qids.py
countries.yaml · grapes.yaml · regions.yaml are the human-authored canonical tier (names, colour, hierarchy, synonyms). resolve_qids.py resolves names → Wikidata QIDs into qids.lock.yaml (label + description per pick, reviewable in a diff). The v1 sparql/*.rq firehose is gone.
wikipedia/*.py · tests/
Per-country parsers (italy.py, germany.py) contribute region_grapes edges and grape colours only. tests/: allowlist validation, 24-wine coverage against combined.csv, server gate semantics (48 tests).

4 · The LLM local · OpenAI-compatible chat completions

A single local model (default gemma3n:e4b, via llama.cpp llama-server :8080 or LM Studio :1234) is hit at two distinct points with very different request shapes.

Local LLM endpoint — /v1/chat/completions
Call A — Snippet scoring scorer.py
Single-shot, temperature 0.1, no tools. Prompt = BATCH_MATCH_SCORE_PROMPT. Returns a JSON map {idx: 0–100}. One call per product.
Call B — Tag inference tagger.py
Multi-turn tool loop, temperature 0.0, tool_choice:auto, TOOL_SCHEMAS advertised. Up to MAX_ITERS=8 round-trips, MAX_SUBMIT_RETRIES=3. System = SYSTEM_PROMPT_MCP.

6 · Improvements & Findings ordered by severity

Found while reading the tree. Severity reflects impact on a real run, not effort to fix.

Fixed
DDG package mismatch — the searcher gathers nothing
Resolved 2026-09-15: searcher.py imports ddgs, falls back to duckduckgo_search, and raises if neither is installed.
fermentation/searcher.py:14 · requirements.txt:1
searcher.py does from ddgs import DDGS inside a try/except ImportError that sets DDGS=None. But the pinned/installed package is duckduckgo-search==8.1.1 (imports as duckduckgo_search), not ddgs. So the import silently fails, DDGS stays None, _ddg_snippets() returns [], every product gets no web_context, and 100% of wines route to needs_review — with no error.
  • Fix: either change the import to from duckduckgo_search import DDGS, or add ddgs to requirements.txt (it's the renamed successor) and drop duckduckgo-search. Pick one and align both files.
  • Harden: the bare except ImportError: DDGS=None turns a missing dep into silent zero-result runs. Log a loud warning (or fail fast) when DDGS is None at startup.
Fixed
library.db is still the v1 "firehose" — the allowlist reseed is unbuilt
fermentation/library_mcp/library.db · BATON.md
Resolved 2026-09-15: allowlists + QID lock, two-tier DB, canonical-first server with is_phrase/is_placeholder, new submit_tags issue codes (unknown/placeholder region & grape), parent-chain expansion, and 48 tests. Note: every hand-typed QID in the original BATON was wrong — the plan was reworked to name-keyed allowlists with machine-resolved QIDs (see BATON.md).
The baked DB holds 1672 grapes (1671 with no color), 213 countries (incl. historical states), and only 36 regions — exactly the noise BATON.md set out to replace. Meanwhile server.py, schema.sql, and build_db.py have no is_canonical column, no region_synonyms table, and no allowlist/ directory — none of the documented reseed exists yet.
  • With 36 regions, submit_tags will reject most real regions as non-canonical, looping the tagger until it gives up → more needs_review.
  • Fix: execute BATON.md Tasks 1–8 (schema + region_synonyms, allowlist YAMLs, VALUES-bound SPARQL, placeholder pass, QID-aware Wikipedia parsers, canonical-first server resolution, CI coverage test). This is the single biggest lever on output quality.
High
Confidence threshold (90) is unreachable for most wines given the prompt's hard caps
fermentation/constants.py:24,38 · SYSTEM_PROMPT_MCP
DEFAULT_CONFIDENCE_THRESHOLD = 90, but the tagger prompt instructs the model to cap confidence at 84 when only one snippet contributed and the scorer's producer gate already drops producer-absent snippets while SNIPPET_MATCH_THRESHOLD = 85 + TOP_N = 3 means many wines reach the tagger with a single surviving snippet. Net effect: a correctly-tagged single-source wine maxes at 84 < 90 and is forced to needs_review regardless of correctness.
  • Fix: lower the default to ~80 (so a clean single-source wine can auto-pass), or relax the single-snippet cap. Tune these two numbers together — they're coupled and currently fight each other.
  • SNIPPET_MATCH_THRESHOLD = 85 is also aggressive: the scoring rubric only awards 90–100 to "this exact wine, all details confirmed." Consider 70–75.
Medium
Cutover is incomplete — no run.sh, thin test coverage
fermentation/ (no run.sh) · fermentation/library_mcp/tests/
There's no fermentation/run.sh (PLAN Phase 4 unmet), and tests cover library_mcp only.
  • Fix: add fermentation/run.sh (dep check + python -m fermentation.ferment).
  • Add tests for the pipeline modules — there are currently no tests covering searcher/scorer/tagger/ferment.
Medium
No snippet caching — reruns re-hit DuckDuckGo for every wine
fermentation/searcher.py · PLAN.md Risk #7
There is deliberately no snippet cache. Every rerun re-queries DDG (≥4 queries/wine + politeness sleep), which is slow and risks rate-limiting during iteration — and DDG failures silently yield zero snippets (see #1), so a throttled run looks identical to a successful all-needs_review run.
  • Fix: add a simple keyed cache (by product id or query hash) with a TTL, gated behind a --no-cache flag. Pairs naturally with debug-output's per-product JSON.
Medium
MCP subprocess has no health-check / restart — one crash stalls the whole run
fermentation/tagger.py · PLAN.md Risk #3
The stdio server is spawned once per run inside a context manager. If it dies mid-batch, every subsequent call_tool raises and each product burns its retry budget. The loop is also fully synchronous over a background event loop with fixed timeouts.
  • Fix: wrap call_tool with a liveness check and a single re-spawn on failure, or at minimum detect a dead session and abort cleanly with a clear message rather than silently degrading.
Fixed
Server does Python-side full-table scans on every resolve miss
Resolved 2026-09-15: resolvers now hit in-memory accent-folded indexes built once at startup (names, synonyms, ISO codes).
fermentation/library_mcp/server.py — _resolve_country/region/grape
Each resolver tries an indexed COLLATE NOCASE match, then on miss loops the entire table in Python doing _fold() per row. With 1672 grapes that's a full scan per failed lookup, several times per product.
  • Fix: store a precomputed folded column (or a folded_name index) and resolve with a single indexed query. Eliminates the per-row Python loop entirely.
Low
tag_log stores the full transcript (incl. system prompt) per product
fermentation/ferment.py — log_tag / tag_log table
Every product writes its entire message history — system prompt, tool schemas echoes, all turns — as a JSON blob. Useful for audit, but it bloats wines.db and duplicates the static system prompt on every row.
  • Fix: store only the tool-call/result turns (drop the system + user boilerplate), or gate full transcripts behind --debug-output which already writes them to disk.
Low
Two divergent confidence rubrics live in prompt text
constants.py — BATCH_MATCH_SCORE_PROMPT vs SYSTEM_PROMPT_MCP
The scorer and tagger prompts each embed their own (overlapping but not identical) scoring bands and abbreviation guides. They'll drift over time and the abbreviation guide is duplicated verbatim.
  • Fix: extract the shared abbreviation guide / band definitions into a single constant and interpolate it into both prompts.
