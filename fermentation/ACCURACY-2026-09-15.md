## Root causes and what was changed (2026-09-15)

1. **`no_grapes` was a hard rejection with a hint that said "submit anyway".**
   `submit_tags` returned `ok: false` for an empty grape list while its hint
   told the model the row would route to needs_review. The model obeyed the
   hint, was rejected up to 3 times, and `infer_tags` returned `None` — so
   the country and region it had already resolved were discarded. This is
   the entire Aster / Curator story.
   *Fix:* empty grapes are accepted (`ok: true`, `warnings: ["no_grapes"]`);
   `decide_tag_status` routes empty-grape rows to `needs_review`. Aster now
   lands as `Spain; Ribera del Duero; Castilla y León` + needs_review.
2. **Search failures were invisible.** `_ddg_snippets` swallowed every
   exception and returned `[]`, so a throttled engine looked like an obscure
   wine. *Fix:* per-query errors are recorded in the search log and shown in
   the drawer; a wine with zero results from all queries is retried after
   15 s and 45 s; ddgs timeout raised 5 → 10 s.
3. **Scorer failures were invisible.** The raw LLM reply was not logged, so
   an all-zero scoring (Li Veli) could not be diagnosed. *Fix:* reply,
   parse result and error are stored under `llm` in the scorer log; a reply
   with no JSON is retried once with the strict suffix (which existed but
   was never used); temperature 0.1 → 0 (a 0 ↔ 98 swing on the same snippet
   between two runs was observed).
4. **Producer gate ignored the URL.** Site-scoped queries return page
   descriptions that often omit the producer while the URL slug has it.
   *Fix:* the gate now checks body + URL.
5. **The abbreviation guide primes guesses.** Two of the three wrong `model`
   rows (Chocapalha → Tempranillo, Massaya → GSM) map directly onto lines in
   the guide; Li Veli's all-zero scoring reproduces with it and vanishes
   without it. The library already resolves every abbreviation the guide
   lists (`lookup_grape("PN")` → Pinot Noir), so in the tagger it is
   redundant. See the A/B result below.
6. **Context was too thin for the confidence rubric.** 300 chars per
   snippet for scoring, top-3 for tagging. *Change:* 600 chars for scoring,
   top-5 snippets of up to 2000 chars for tagging (~2.5k tokens; the MCP
   prompt carries no reference tables so there is room), plus the
   distributor's own site (winebow.com, monsieurtouton.com) and two big
   retailers (wine.com, totalwine.com) as sources.

## Abbreviation-guide A/B (same run's search logs, both variants)

_Scorer_ (24 wines × with / without): 16/24 identical web_context sets.
For calibration, re-running the *same* prompt against the logged run gave
21/24 identical, so roughly 5 of the 8 differences are the guide, not noise.
Li Veli is the decisive case: with the guide all six true matches score 0;
without it they score 89 and a web_context is built.

_Tagger_: only the "with" half completed before the test was stopped (per
Maxwell, to free the llama-server). At temperature 0 it reproduced the
original run's submissions exactly for all 12 wines it reached, which at
least confirms the tagger is deterministic and the wrong grapes are not
noise. Decision taken on the scorer evidence plus the mapping of the wrong
guesses onto guide lines: the guide is **removed from the tagger prompt**
(the library's `lookup_grape` already resolves every abbreviation it listed)
and **replaced by a one-line note in the scorer prompt**. The tagger rubric
now also says grapes must be named by a snippet, never inferred from
region/style/name, and that "… Blend" wording means is_blend=true.

## Context selection (added later on 2026-09-15)

- **Near-duplicate dedupe** in the searcher: word-set Jaccard ≥ 0.9
  (digits ignored) collapses e.g. one Wine-Searcher price page returned for
  three vintages; 53 of the run's 340 snippets. Applied on write and, for
  older logs, on read.
- **Source-diverse top-N** in the scorer: the distributor's snippet first
  (if it survived), then the best snippet from each distinct source, then
  by score. Same token budget, more distinct facts. The 2000-char cap was
  left alone: the median DDG body is ~550 chars and only 8/340 reached the
  old 1500 cap, so a higher cap admits nothing useful.

## Search-query experiment (later on 2026-09-15)

11 wines (the failures plus a few controls) × 15 query templates, one engine
order (yahoo → bing → ddg), 3 results each. A result "passes the gate" when
body + URL contains a product-name token; "grape" / "region" mean a
gate-passing result names the wine's hand-checked true grape / region.

Reading: question-style queries are the best single thing we can send — the
engines turn "what grapes are in X wine" into importer/retailer pages that
say things like "100 % Tinta del País (Tempranillo)" or "Massaya Rose 100 %
Cinsault", exactly the sentence the tagger needs, and 127 of their 165
results were URLs no site-scoped query returned. The UPC helps only as a
plain query (site-scoped UPC queries are mostly junk). The distributor site
helps when indexed (DV Catena, Faustino, La Rioja Alta) and costs one cheap
query, so it stays. Total Wine is dropped (slow, timeouts).

New plan (`SEARCH_QUERIES` in constants.py), 9 queries per wine instead of
12: Grapes Q, Region Q, Wine Searcher, Vivino, CellarTracker, Wine.com, UPC,
distributor, plain fallback.

## Still open / next steps

- **Grape hallucination when context is silent** (Chocapalha, Librandi,
  Massaya). The prompt already says "submit an empty list rather than
  guess". Options, cheapest first: (a) drop the abbreviation guide (done if
  the A/B agrees); (b) add a rubric line "if no snippet names a grape,
  grapes MUST be []" and cap confidence at 60 when grapes are not quoted
  from context; (c) post-check: reject a `model` row whose grapes do not
  appear (or a synonym) anywhere in web_context — mechanical, cheap, and
  would have caught all three.
- **is_blend from context wording**: "Tempranillo Blend" → is_blend should
  be true even with one named grape. Rubric line.
- **Region coarseness** (Bayten): only fixable with better sources — the
  distributor site query should help.
- **Search throttling**: the retry helps but a throttled 24-wine run still
  loses time. If it persists, run the search phase with `DDG_CONCURRENCY=2`
  or add a second backend (`DDG_BACKEND="duckduckgo,bing"`).
- **Non-barcode SKUs** (Urruzola `12134`) get no UPC queries; nothing to do
  unless Lightspeed has the real UPC.
