### 1. Engine answer-blobs — `searcher.split_aggregate_bodies()`

Yahoo/Bing return a spliced body gluing several results together under one URL.
Curator White's `grapewitches.com` snippet absorbed the winegoddess body, an
Easterly tech sheet, a Vivino line naming a *different vintage's* blend
("Made from Sémillon, Chardonnay, Chenin Blanc"), and an unrelated paragraph
about Madiran. `evidence.unsupported_grapes` passed Sémillon because it *was*
literally in `web_context`. 70 of the run's 309 snippets were such blobs
(median real body: 245 chars).

A body ≥ `SNIPPET_BLOB_MIN_CHARS` that verbatim-contains ≥2 other snippets'
whole bodies from other URLs is cut back to the text before the first foreign
segment. Replay: **18 trimmed across 24 wines, no wine left without snippets,
context membership held everywhere.**

### 2. Containment dedupe — `searcher.dedupe_near_duplicates()`

Chocapalha's merchant sentence came back from `vivino.com`, `vivino.com/US` and
`falstaff.com` at Jaccard 0.844 / 0.887 / 0.745 — under `SNIPPET_DEDUPE_JACCARD`
only because each copy was truncated at `SNIPPET_CHAR_LIMIT` at a different
offset. New rule: two bodies *both* ≥ `SNIPPET_BLOB_MIN_CHARS` with overlap
coefficient ≥ `SNIPPET_BLOB_CONTAINMENT` are the same blob. **Gated to
long-vs-long deliberately** — applied generally, containment matched 133 pairs
on this run, because a short body's words are routinely a subset of a long
one's. Replay: 7 extra duplicates dropped.

**Correction worth carrying forward:** this does *not* change Chocapalha's
confidence. Its `Region Q #2/#3` never entered the context (4 distinct source
families before and after), so the "triplicate inflated confidence to 85" claim
made mid-session was wrong. Syrah shipped because one merchant sentence named
four grapes and nothing requires cross-source agreement on a *grape*.

### 3. Name-coverage note — `scorer._name_coverage_note()` + prompt change

Root cause of the zeros, confirmed by asking the model to explain itself: it
reads **extra words as evidence of a different wine**.

- "Masseria Li Veli Passamante" → "the producer does not match" (it is a superset)
- "Bodegas Aster **by La Rioja Alta**" → parsed the producer as the *region*
  La Rioja, then declared a conflict with Ribera del Duero
- "Txakoli" vs "Txakolina" → "different wine type" (same word, Basque declension)

**45 of the 261 snippets containing every distinctive word of the product name
scored 0**, including the snippets carrying the true blend for Bila Haut
(`"Grape: Syrah, Grenache, and Carignan"`) and Curator White (`"Chenin Blanc,
Chardonnay, and Viognier"`). Bayten lost 7 that way, which is why its region
was wrong in the earlier run.

Two changes: the prompt now says the name is POS shorthand that drops the
producer; and a per-snippet note states the coverage outright, as the URL hint
already does. Batch-mode replay over 9 wines: **22 up, 2 down** (both toward
their logged value), **1 false promotion**.

`_is_list_page()` guards that false promotion — a Winebow portfolio index
containing "mont" and "gravet" by accident went 0 → 70. Real list pages measure
98–100% capitalized words, prose 13–43%; threshold 0.7.

**A minimum-token guard was proposed and rejected on the data:** Mont Gravet has
2 distinctive tokens (would not have been blocked) and `Curator White` has 1
(would have been blocked, losing a 0 → 100 recovery). Reasoning is in the
constant's comment so it does not get re-proposed.

```python
import sys; sys.path.insert(0, "/Users/mgraeser/Documents/Wine Warehouse DDD")
import json, glob
from fermentation import scorer
from fermentation.types import Snippet, Product
API = "http://localhost:8080/v1/chat/completions"
MODEL = "bartowski/Qwen2.5-7B-Instruct-GGUF"

logged = {}
for f in sorted(glob.glob('logs/20260915-221614/scorer/*.json')):
    d = json.load(open(f))
    logged[d['name']] = {m['source']: m['match_score'] for m in d['scored_snippets']}

up = down = same = 0
for f in sorted(glob.glob('logs/20260915-221614/search/*.json')):
    d = json.load(open(f)); name = d['name']
    snips = [Snippet(source=s['source'], domain=s.get('domain', ''),
                     body=s['body'], url=s.get('url', '')) for s in d['snippets']]
    prod = Product(id='x', name=name, sku='', brand=None, category=None,
                   supply_price=0, retail_price=0, supplier=None, items_sold=0,
                   margin_pct=0, sale_count=0, customer_count=0, avg_sale_value=0)
    res, _ = scorer._batch_match_score(prod, snips, API, MODEL)
    lg = logged.get(name, {})
    rows = []
    for i, s in enumerate(snips):
        old, new = lg.get(s.source), res.get(i, (None, []))[0]
        mark = ""
        if (old or 0) < 70 <= (new or 0): mark = " UP"; up += 1
        elif (old or 0) >= 70 > (new or 0): mark = " DOWN"; down += 1
        else: same += 1
        if mark: rows.append(f"    {s.source[:26]:26}{str(old):>6}->{str(new):>4}{mark}")
    if rows:
        print(f"=== {name}"); print("\n".join(rows)); sys.stdout.flush()
print(f"\nTOTAL up={up} down={down} unchanged={same}")
```

## Known-broken, deliberately not addressed

- **Cuvée conflicts are not detected.** Neirano Barolo **Riserva** — a genuinely
  different wine — scores 90 with *and* without these changes. The identity gate
  is loose in both directions; the coverage note does not make this worse.

  **Possible improvement:** warn the scoring model that when a source's wine
  name has a quality/cuvée qualifier that is **not** in the searched name, it is
  probably a different wine: lower confidence or flag `needs_review`. If the
  searched name already has the qualifier ("Gran Reserva"), a source that has
  it too is fine. Qualifiers to watch for, grouped so that translations of the
  same word count as a match (search "Reserve" + source "Riserva" = OK):
  - *Reserve:* Reserve, Reserva, Riserva, Réserve, Reservado, Private /
    Proprietor's / Special / Family Reserve, Réserve de la Famille
  - *Grand reserve:* Gran Reserva, Grande Réserve, Grande Reserva, Riserva
    Speciale
  - *Crianza/aging:* Crianza, Joven, Roble
  - *Cru/classification:* Grand Cru, Premier Cru / 1er Cru, Grand Cru Classé,
    Cru Bourgeois, Erste Lage / Grosse Lage / GG (Grosses Gewächs), Classico,
    Superiore, Selezione, Gran Selezione
  - *Old vines:* Old Vines, Vieilles Vignes, Vecchie Vigne, Alte Reben, Viñas
    Viejas, Vinhas Velhas, Ancient Vines
  - *Site/selection:* Single Vineyard, Vigna, Vigneto, Clos, Lieu-dit,
    Barrel Select, Special Selection, Sélection de Grains Nobles,
    Tête de Cuvée, Cuvée Prestige, Limited Edition, Icon
  - *Ripeness/sweetness:* Kabinett, Spätlese, Auslese, Beerenauslese,
    Trockenbeerenauslese, Late Harvest, Vendange Tardive, Passito
  - *Style variants:* Rosé / Rosato / Rosado, Blanc de Blancs, Blanc de Noirs,
    Ripasso, Appassimento
  Watch-outs: only count a qualifier that sits outside the producer name (e.g.
  a "Clos ..." producer). Accent- and case-insensitive matching. The model alone
  is unreliable here, so this could be a deterministic per-snippet note like
  `_name_coverage_note` ("source names qualifier X; searched name does not").

- **Scores are not reproducible across `llama-server` restarts** even at
  temperature 0: on identical prompts, Aster Vivino #1/#2 went 95 → 0 and

  The comment in `constants.py` claiming temperature 0 made this deterministic is

- **Grape corroboration.** `evidence.unsupported_grapes` searches the whole

## Methodology note for whoever picks this up

Single-snippet ablation **is not a valid proxy** for the pipeline. The same
snippet scores differently alone than in its real batch (Neirano Riserva: 0
logged, 95 alone; Zenato generic: 0 logged, 90 alone). Exact batch reproduction
matched the log perfectly. Always replay through real batches.

Also: `llama-server` runs on Metal, so **low CPU% does not mean idle** — that
misread cost a detour mid-session. The `python` process sitting at 0% with an
ESTABLISHED socket to :8080 is normal while generating.
