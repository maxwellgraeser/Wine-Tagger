# Scoring methodology review — 2026-09-15

Companion to `ACCURACY-2026-09-15.md` (per-wine accuracy of run
`20260915-151731`). This document covers the **snippet match score**: whether
the confidence the scorer attached to each snippet reflected whether that
snippet was actually about the wine and useful, and what was changed as a
result. Evidence run: `20260915-170657` (24 wines, Qwen2.5-7B-Instruct,
threshold 85, producer gate on). Verification runs: two replays of the same
search logs (`…170657b` at threshold 85, `…170657c` at threshold 70) and a
fresh 3-wine run (`20260915-210032`).

## Verdict on the original method

The match score was **not a calibrated confidence**. It was a
"does the product name appear here" detector with a large random hole in it,
and nothing downstream checked the tagger's answer against the text it was
shown.

| Finding | Evidence (run 20260915-170657) |
|---|---|
| The model omitted indices from its reply and the code scored them 0 (`raw_scores.get(i, 0)`) | 17 of 24 wines had fewer keys than snippets; 72 of 255 gate-passing snippets with the product name in the body were omitted (28 %); 38 of 174 grape-naming snippets became 0 this way |
| Scores were bimodal (0 or ≥ 85) | Only Zenato used the 10–80 range; `SNIPPET_MATCH_THRESHOLD = 85` therefore split "listed" from "not listed", not "confident" from "unsure" |
| The scorer never saw the URL | Vivino / CellarTracker bodies read "A White wine from Calabria. Made from Greco Bianco." with the producer only in the slug; Librandi's two such snippets scored 50 and were excluded, the only context snippet had no grape |
| The rubric measured identity, not information | Selection was score → source diversity, so "Shop Aster Ribera del Duero Crianza at the best prices" (98) and a CellarTracker UPC-code dump (90) filled the context while the tech sheet naming the blend sat at 0 or 6th |
| Nothing verified the tagger against the context | Aster: context named no grape, tagger committed Tempranillo at 85 → `model`. Bila Haut: one snippet about a different cuvée (V.I.T.), no grapes, tagger committed Cinsault/Grenache/Carignan at 89 → `model`, ignoring the prompt's own "max 84 for one snippet" |

Snippets that were correct but scored 0 through omission included the most
fact-dense ones in the dataset: Pav Chavannes' CellarTracker row "Producer
Domaine du Pavillon de Chavannes, Variety Gamay, Appellation Côte de
Brouilly"; Vajra's Vivino "Made from Nebbiolo"; La Rioja Alta's "some 25 %
Garnacha in the blend"; Urruzola's retailer page listing Hondarrabi Zuri and
Hondarribi Beltza.

## The revised method

Implemented in `scorer.py`, `evidence.py`, `phases.py`, `searcher.py`,
`constants.py`; described normatively in `PLAN.md` → "Phase 3".

1. **Batched, per-index scoring.** `SCORING_BATCH_SIZE = 8` snippets per
   call, each with its URL. The prompt names every index it expects; any
   index missing from the reply is re-asked (`SCORING_MISSING_RETRIES = 2`
   rounds). Still-missing indices are logged as `dropped_reason:
   "unscored"`. On the replays: 0 unscored across 24 wines.
2. **URL-only name hint.** When a word from the product name is in the URL
   but not in the text, the line says so. Needed because even with the URL
   shown the model scored Aster's Vivino Tempranillo pages 0 on the fresh
   run; with the hint they scored 95.
3. **Score + facts.** Each entry is `{"score": 0–100, "facts": [...]}`
   with facts ⊆ {grape, region, producer}. Score gates identity; facts
   drive selection (`_fact_rank`: grape named → number of facts → score),
   then distributor first, then one per source family, then the rest.
4. **Threshold 70.** With honest grading the 70–84 band on the replay was
   almost entirely true matches (Li Veli ×7, Cloudline ×6, Chapelle
   Bastion ×4, Bayten ×3); at 85 Li Veli and Neirano lost their context
   entirely.
5. **Evidence rules on the tagger's output** (`apply_evidence_rules`):
   a submitted grape absent from `web_context` (canonical name or library
   synonym; generic synonyms like "Tinto" excluded) → `needs_review` with
   `review_reasons: ["unsupported_grape:<name>"]`; one snippet in context →
   confidence clamped to 84.
6. **Search hygiene.** `BLOCKED_DOMAINS = {vinovoss.com}` (AI-generated;
   its Mont Gravet page says Côtes de Gascogne, the importer says
   Languedoc). The throttling retry also fires when ≥ 50 % of a wine's
   queries raised (Bila Haut: 9 of 11 timed out, four junk results skipped
   the retry).
7. **Category** (separate request, same change set): `submit_tags` accepts
   an optional `category` ∈ {Red, White, Rose, Sparkling}; used only when
   the CSV has none, stored with `category_source: "model"`.

## Known limits / next

- **Region specificity.** On the replay four wines came back one level
  coarser (DV Catena → Mendoza, Excelsior → Breede River Valley, Urruzola →
  Basque Country, Vajra → Piedmont) although the specific region is in the
  context. Tagger-side; a rubric line "submit the most specific canonical
  region the context supports" is the next thing to try.
- **Scorer misses on abbreviated names** ("Pav Chavannes"): the true match
  scored 0 with no omission involved. The evidence rule catches the
  consequence; a name-expansion hint (like the URL hint) could catch the
  cause.
- **Mojibake in snippets** ("Tinta del Pa¡s") defeats synonym matching.
- **Tagger confidence variance** (Bayten 90 → 80 on the same evidence) is
  now visible as review churn at the threshold. Temperature is already 0.
- Replay `…170657c` logs were deleted after the run; the tables above were
  captured from its `final/` files before deletion. `…170657` (evidence) and
  `…170657b` (threshold-85 replay) are kept.
